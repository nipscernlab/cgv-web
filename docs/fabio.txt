Done, but with one extra change worth flagging before you install. While
preparing the package we noticed that the previous backend kept a single
process-wide watched folder, mutated by POST /api/xml/set-folder. That
meant two operators on different PCs would step on each other's view:
last writer wins, for everyone. Wrong shape for a desk tool.

2.2.0 fixes that. The backend is now stateless: each request carries the
folder it wants. The XML_FOLDER default is still honoured, but only as the
prefill returned by GET /api/xml/default, which the UI uses on a first
visit. Every browser/tab keeps its own choice in localStorage and can
switch streams from the pencil, independently of every other client.

So, to your question: yes, /etc/sysconfig/cgv-web now ships

    XML_FOLDER=/atlas/EventDisplayEvents/physics_Main

active by default. The file remains %config(noreplace), so on upgrade an
existing file is kept; if it was not modified locally, the new default
takes effect, otherwise you will see cgv-web.rpmnew next to it.

API change to be aware of for your reverse proxy:
 - GET /api/xml/default                         (always 200, JSON)
 - GET /api/xml/list?path=<dir>                 (200 or 4xx)
 - GET /api/xml/file?path=<dir>&name=<basename> (200 or 4xx)
 - POST /api/xml/set-folder is gone. The proxy no longer needs to forward
   POST for the SERVER feature; GET-only is enough.

Verify after install:
    curl -s https://pc-atlas-www.cern.ch/cgv-web/api/xml/default
        -> {"path": "/atlas/EventDisplayEvents/physics_Main"}
    curl -s "https://pc-atlas-www.cern.ch/cgv-web/api/xml/list?path=/atlas/EventDisplayEvents/physics_Main"
        -> JSON array of the newest .xml (during a run)
